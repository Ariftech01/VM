Long-running AI assistants often lose important details as chat histories exceed context limits. Existing approaches can either retain expensive full transcripts, discard facts through fixed windows, or create summaries that are difficult to inspect and reverse. GitMem is an offline-first proof of concept for versioned, user-controlled agent memory. It ingests dialogue into typed memory units, scores each unit with explainable signals, and maintains source-linked summaries only when deterministic checks preserve detected names, numbers, dates, and negations. A local SQLite store records immutable revisions, commit snapshots, decisions, tags, branches, and answer provenance. Git-like operations support restore, selective rehydration, editing, merge review, cherry-pick, and history inspection. Retrieval reconstructs a bounded context with an exact knapsack optimizer and provides TF-IDF when local embedding models are unavailable. A deterministic mock language model keeps the demo reproducible and offline; optional Ollama, Gemini, and OpenAI-compatible adapters support live inference. Critical facts can be protected with canary questions, bisected across history, and recovered from a known-good snapshot. PII shredding removes stored text while retaining hashes for integrity auditing. The Streamlit interface exposes chat, memory explanations, history, operations, attribution, canary checks, and benchmark reports. Evaluation compares GitMem with full-history, sliding-window, rolling-summary, and retrieval baselines on synthetic conversations, reporting token use, estimated cost, latency, accuracy, critical-information recall, and recovery success. The prototype prioritizes auditability and recovery, while acknowledging rule-based scoring and synthetic data limitations.
